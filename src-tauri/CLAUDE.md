# src-tauri: Rust core

A thin data and actions layer between the UI and the user's herdr-core (`hc`). The UI derives the views; Rust connects, subscribes, executes and launches.

## Module map (from the plan's file map; keep to it)

| Module | Owns |
|---|---|
| `core/` | the herdr-core client (v0.9): `connection.rs` (`Connection`: JSON-RPC lines over any async reader and writer, one reader task, `Notification`, the `Connector` trait), `client.rs` (`CoreClient`: the one door, a pool of at most 4 connections, `call_long` for one-shot connections, `hello`, `USES`, `timeout_for`, `ProcessConnector` that runs `<bin> connect`), `errors.rs` (`CoreError`), `display.rs` (the `hc` command line the log shows), `locate.rs` (`locate`: the saved path, the login shell's `herdr-core`/`hc`, then the usual folders; a binary counts only if `--version` prints `hc X.Y.Z`; `find_legacy_herdr` is permanent: with no core it looks for a herdr 0.9 binary and its version, only so onboarding can say it was retired, and it runs with `legacy_forwarded_env`, never an `HC_*` name) and `log.rs` (`CommandLogEntry`, `CommandLog`: the 200-entry ring `CoreClient` writes; `log_note` adds a command handed to a terminal (method `launch`), `log_launch_failure` one the app ran itself that failed (`herdr-app do`, method `launch`, with its exit code and error) and `log_event` something the app did on a connection it holds, the subscription (method `event`, which the drawer shows without a Copy button)), `model.rs` (lenient serde records: `CoreTerminal`, `CoreMachine`, `TemplateInfo`) and `events.rs` (`TerminalMap`: a snapshot plus the notifications applied to it, pure) and `layout_doc.rs` (`parse`: herdr-app's `herdr-app` layout document to a `SpaceLayout`, tolerant and read-only: only `content.terminal` of `block` nodes and of `floating[]`, never `props`; `sync.rs` reads it with quiet `doc.get`s, never `doc.set`) |
| `agents.rs` | pure classifier (v0.9): `classify(CoreTerminal, own_seen, restarts)` gives the `TerminalView` the UI renders (`DisplayStatus`, kind for the logos, `herdr.seen`/`herdr.pinned` labels); `KNOWN_AGENTS` holds each kind's `app` aliases, start argv (codex has `--no-daemon`) and whether its prompt is positional |
| `env.rs` | login-shell env capture and `login_command_v`; the environments handed to a spawn (`forwarded_env`: the eleven names the core needs, never `HC_TERMINAL_*` or `HC_SCOPE`; `legacy_forwarded_env`: the first six only, for the legacy probe; `herdr_app_env`); `run_plain_text` (`--version` probes: the core, the legacy herdr, `herdr-app`; `herdr-app status`). Captured and resolved after the window is up; `get_state` answers `null` until then. The version floor lives in the UI (`lib/format.ts`) |
| `activity.rs` | `ActivityV2`: the person's own seen record per (machine id, machine-local address), `on_status` (the `Transition`s worth a notification; never for a worker), persisted to `activity.json` as `{"version":2,…}` (a v1 file is ignored); `flush()` runs on exit |
| `state.rs`, `sync.rs` | `state.rs`: `AppState`/`MachineView` (with the core's own `state` word, `None` for Local, and `via`)/`Health`/`CoreState` (what the UI sees; terminals per machine, addresses machine-local). `sync.rs`: `CoreSync`, event-driven from `events.subscribe` plus `machine.list`; emits the `"state"` event (coalesced to one per 100 ms) and hands each `Transition` to a `NotifySink`. A dropped stream is retried with backoff for 2 minutes, then `Stopped` until `reconnect_now`; a stream that ends after a local terminal ended with `server_stop` (`hc server stop`) goes to `Stopped` at once, and a core missing after the first subscribe is retried like a drop (`hc update` swaps the binary). Background calls run only while the event connection is up (`is_online`): layout reads, seen writes and the machine list here, the preview through `SyncCell::may_preview`, the New session sheet's check and templates through `machine_online`. `SyncCell` holds it in Tauri state, empty until the core is located (`get_state` answers `null` before). Shared seen: `set_looking` gives it the looked-at terminals, and it writes `herdr.seen=<turn>` (a string, through `call_quiet`, Ruling C79) for those whose label is missing or lower, at most once per turn (`last_written_seen`, so a Mark as unread stands until the next turn), deciding when the set changes, on a `turn` event and on a new baseline; every write also moves `ActivityV2::mark_seen` |
| `actions.rs`, `commands.rs` | New session on `terminal.run`: pure `run_params(req, machine_name)` (exactly the schema's param names; `labels {"herdr.seen": "0"}`, the TERM/COLORTERM env, `on` only for a remote), `validate_name`, `preview` (`display("terminal.run", …)`), and `NewSessions` (`run_choices`: `KNOWN_AGENTS` filtered by one quiet `machine.exec` per machine, cached in `KindsCache`, a failed check lists every kind; templates for Local only; `create`: `call`, or `call_long` for a template, answering the machine-local address). Also `MachineActions` (the Workbox screen's `machine.connect`, `machine.rename` (the new name checked by `validate_name`) and `machine.rm`, by the machine's current name from `CoreSync::machine_name`; each, a failed one too, ends with `refresh_machines`; Local is refused) and `machine_command_args(verb, name)` (`["machine", verb, name]` for the Log in… and Update hc there… tabs, the name checked by `validate_name`), `AddMachineRequest` with `check_add` (one of `target` (+ `port`, joined as `host:port`) or `via`, a name `validate_name` accepts, a session `[A-Za-z0-9][A-Za-z0-9._-]{0,63}`, a `via` without a backslash or control character that needs a name) and `add_params` (exactly the schema's names), `MachineActions::add` (`machine.add` through `call_long`, 60 s; answers the new machine's id, then `refresh_machines`; the core's typed errors (`hc_missing`, `incompatible`, `needs_login`, `unreachable`, `name_taken`, `already_added`) stay `ActionError::Core`, a timeout is `MaybeApplied`) and `preview_add` (the `hc machine add …` line), and `RowActions`; `commands.rs` holds only the `#[tauri::command]` wrappers and their small helpers |
| `terminal/` | `attach.rs`: `attach_argv(core, full_address, observe)` (`[core, "attach", ["--observe",] addr]`, the same for Local and remote), `attach_display`, `allowed_core_args` (the allowlist: `attach`, `machine login|update <name>` (a name `validate_name` accepts), `machine add` with exactly one of a target and `--via` (no backslash or control character; needs `--name`), `--name` (`validate_name`), `--session`, `--temp` and `--install`, each once) and `machine_add_args(req, install)` (the arguments only for an add; `--install` only when `install` is true, which the UI sets after a confirm) and `checked_core_argv` (prepends the resolved core; the UI never sends a binary); `shell_quote`, one launcher per terminal app; `open.rs` is what "Open" runs (the launch spec and the command-log note) and takes the home dir, so it knows nothing of Tauri; `session.rs` is `TermSessions`: the in-app terminal's open sessions (writer, `PtyControl`, a reader thread that decodes UTF-8 incrementally and pushes `TermEvent::Data`/`Exit` to a sink; it keeps the last 4 KB of output, and `Exit` carries `last_line`, the last non-empty line with escape codes removed, where a `hint:` gives way to the `error:` line before it) |
| `preview.rs` | `PreviewManager` (the live preview, emitting only changed frames, reading only while `may_read`: the window is on screen and the event connection is up), `PreviewFrame`, `read_screen`/`read_tail`: both read `terminal.read {terminal, lines: 0}` through `CoreClient::call_quiet` (never `lines > 0`); the full address is looked up at every read (`FullAddress`), and `preview_error` words a failed read |
| `herdr_app.rs` | Herdr, the desktop app (v0.9, spec 8.5): `parse_app_version` (the first line must start `herdr-app `), `app_candidates`/`locate_app` (the login `PATH`'s absolute entries, `~/.local/bin`, `~/Applications/Herdr.app/Contents/MacOS/herdr-app`, then the folders of `system_app_dirs()` (`/Applications`); the first that prints a `herdr-app` version wins; `locate_app_in` takes the folders, so tests never reach a real install), `window_open` (`herdr-app status` exits 0; 2 means no window), `HerdrApp` (Tauri state: the located path, found again when it is gone, and the `status` answer cached 5 s), and `open_in_herdr` (`[app, "do", "terminal.peek", {"terminal": <full address>}]`, the JSON built by `serde_json`, run directly with `env_clear` and `env::herdr_app_env(login, socket_from)`: the base six from the login shell plus `HERDR_APP_HOME` and `XDG_CONFIG_HOME` taken first from this process's own environment (Ruling C103: a Dock-launched Herdr.app has the launch environment, not the shell's), then, if `status` fails and the login shell's values differ, once more from the login shell; the winning environment is cached with the 5 s `status` answer and the click uses it; never an `HC_*` name; `do` failures read the JSON `error` on stdout (exit 1), a timeout is `MaybeApplied`, and a "no window" exit 2 drops the cached open; logged like a core call (spec 8.5) as `herdr-app do terminal.peek '{"terminal":"buildbox/t7"}'`: through `CoreClient::log_note` ("shown in Herdr") once it succeeded, or `CoreClient::log_launch_failure` (its exit code when it had one, the time it took and the error) when it failed or timed out). `herdr-app` never goes through `allowed_core_args`. ## Rules

- **Every core call goes through `CoreClient`**, so it lands in the command log. The only other spawns are: `<core> connect` (the `ProcessConnector`, one per pooled connection), the plain-text `--version` probes through `env::run_plain_text` (the core, the legacy herdr and `herdr-app`; they print no JSON and are not logged), `herdr-app status` and `herdr-app do terminal.peek` (the person's click; logged through `log_note`), `<core> attach …` on a pty or in a launcher, terminal launchers (`open`, `osascript`, `/bin/sh -c` for custom templates), the login shell for env capture, and `mdfind`. `open`, `osascript` and `mdfind` are run by absolute path (`/usr/bin/…`, the constants in `terminal/mod.rs`), so a hijacked `PATH` can't swap them. No `ssh` is run by the app: the local core relays every remote machine.
- **A new app command goes in three places**, or it is refused at runtime: `generate_handler!` in `lib.rs`, `COMMANDS` in `build.rs`, and the capability JSON (`capabilities/*.json`) of each window that calls it. Windows get exactly the commands their code invokes; `scripts/capabilities.test.ts` enforces the exact per-window grants.
- **Machines are ids in the app and names in the core.** Calls go to the local core, which relays to a remote machine; the machine is the `on` param (or part of a full address, `buildbox/t7`). Local is the machine id `"local"`, which has no `on`. Addresses in state are machine-local (`t7`); `CoreSync::full_address` adds the machine's current name when a call needs it.
- **Mutations never retry automatically.** A timeout becomes `ActionError::MaybeApplied` and triggers a refresh (`CoreSync::refresh_machines`).
- **Quoting:** any user- or herdr-derived string that reaches a shell or AppleScript goes through `shell_quote` / AppleScript escaping. Test it with hostile strings (`' " $ \` ; |`, unicode).
- **No `unwrap()`/`expect()` outside tests and startup wiring.** Return typed errors.
- **Terminal sessions run only argv Rust builds.** `term_open` takes a `TermTarget` (`Terminal {machine_id, address}` or `Command {args}`), never a command line; Rust builds the argv (`term_launch`: the resolved core, then arguments that pass `allowed_core_args`) and spawns it on a pty with the core env (`forwarded_env`, never the legacy list) plus `TERM=xterm-256color` and `COLORTERM=truecolor`. `term_write` carries only keystrokes and pastes. `term_close` kills only the attach client, never a herdr pane; all sessions are killed when the app exits. `TermSessions` allows at most 16 sessions (`MAX_SESSIONS`) and answers the 17th with "Close a terminal tab first (16 open)."
- **Spawning:** use `tokio::process::Command` with `kill_on_drop(true)`, an explicit env (from `forwarded_env`), and a timeout from `timeout_for` (10 s by default; 60 s for `terminal.run` and `machine.add`; 200 s for `terminal.send`; 20 s for `terminal.interrupt` and `machine.exec`; 30 s for `machine.connect`, since a dial can take about 20 s). The one exception is the Custom terminal template (`LaunchSpec::detached`): it may stay in the foreground, so it is started without a wait or a kill.
- **`CoreSync`'s `emit` runs under an internal lock that keeps states in order.** Anything that reacts to the state (tray badge, notifications) reads the `watch` channel that `emit` fills, on its own task. Never call `CoreSync` methods that emit (`refresh_view`, `set_core_path`) from inside `emit`. Lock order: the model, then `ActivityV2`; never call into `CoreSync` while holding the `ActivityV2` lock.
- **Settings** are read at the moment of use (`SharedSettings::get`), so a change applies to the next open without a restart. Only the hidden workboxes, the core path and the global shortcut need work when they change (`settings::changes`).
- **Types shared with the UI** derive `TS` with `#[ts(export, export_to = "../../src/lib/bindings/")]`. Run `cargo test` to regenerate them, and commit the bindings.
- **Testability:** keep logic pure (argv builders, classifiers, parsers) and inject side effects (`emit` callbacks, `exists` predicates), so tests don't need a Tauri runtime.

## Testing

- **Unit tests** live next to the code in `#[cfg(test)]` (the `Connection` tests use an in-memory transport). **Integration tests** in `tests/` run the real `CoreClient` against `../scripts/fake-hc` (a Node script, `#!/usr/bin/env node`) with a temp `FAKE_HC_DIR`; `tests/common/mod.rs` has the shared helpers.
- **fake-hc protocol** (the header of `scripts/fake-hc` has the whole of it): `connect` is a JSON-RPC line server that answers `hello` from `hello.json` and each method from `<method>.json`, or `<method>@<n>.json` for the n-th call; a file holding `{"error": …}` is sent as the error, `{"sleep_ms": N, …}` waits first. `events.subscribe` then plays `events@<n>.jsonl` or `events.jsonl` (`{"sleep_ms": N}` and `{"drop": true}` are control lines). `--version` prints `version.txt`; `attach` prints a screen and exits with a code. Every process and request is appended to `$FAKE_HC_DIR/calls.log`.
- **Fixtures** in `tests/fixtures/hc/` are captured from a real hc in a sandbox and rewritten by hand with generic names (`buildbox`, `api-service`, `/home/dev`); `scripts/check-no-personal-data.sh` scans them. Real captures go only to `../fixtures-raw/` (gitignored), made by `scripts/capture-raw-fixtures.sh`, which refuses to run outside the sandbox.
- **The live test** is `tests/live.rs`: `#[ignore]`, and a no-op unless `HERDR_UI_LIVE=1`. It checks it is on a sandbox core (`HC_SESSION=herdr-ui-qa`, its own `XDG_*` dirs, no `HC_SOCKET`/`HC_TERMINAL_*`/`HC_SCOPE`) before it connects, gives the core only the names in its `PASSED` list, creates one terminal labelled `herdr-ui-qa=1` and kills and removes only that one (a failed cleanup is part of the test's failure), and stops a core only when it started that sandbox core itself: it checks the sandbox socket before it connects, and a `SandboxCore` drop guard runs `<core> server stop` (time-limited, exit status reported) under the same cleared environment, also after an early failure; a core already running there is left running. Its remote leg adds `HERDR_UI_TEST_MACHINE` as a temporary machine on the remote's `herdr-ui-qa` session and checks that session in `machine.list` before running anything there; it never runs `machine rm`. A plain `cargo test` lists it as ignored. See the root `CLAUDE.md` rule 4 for how to run it.
- **Before committing:** `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`.
