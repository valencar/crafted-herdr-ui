# crafted-herdr-ui v0.4: two-row workspace tabs (design addendum)

Date: 2026-10-19
Status: approved in conversation. The maintainer chose option A on the Claude Design canvas "Workspace tabs redesign" on 2026-10-19, and approved §2 and §5 as presented. The canvas is the visual reference; this text is the authority.
Extends: `2026-10-16-crafted-herdr-ui-design.md` (v1), `2026-10-17-v0.2-in-app-terminal-design.md` (v0.2) and `2026-10-17-v0.3-workspace-design.md` (v0.3). They all still hold unless this addendum overrides them. Where they disagree, this addendum wins.

## 1. Intent

The v0.3 tab strip is one thin row: small tabs, with group labels between them. With a few workboxes open it reads as a run of text, not as tabs. The maintainer wants **bigger tabs that look like tabs, like Chrome's**, grouped by workbox with each workbox's sessions inside it, in two rows.

The workspace header becomes two rows:
1. the **workbox row**: Home and one tab per workbox;
2. the **session row**: the tabs of the active workbox, as large two-line tabs.

Separately, ⌘-clicking a link in a terminal fails to copy it on WebKit (§2.4). Links stay copy-only; the copy is fixed.

### What this overrides in v0.3 §2.1
- **"Grouped by workbox"** and **"Group folding"** are replaced by §2.1 and §2.2 below. Folding goes away.
- **"Tab content"** is replaced by §2.2: every state is spelled out on the tab, not just "Needs input" and "Done, unseen". This also overrides v0.3 call 3.
- **"Overflow"** is replaced by §2.2's overflow rule: the All tabs menu moves to the end of the session row.
- Everything else in v0.3 §2.1 holds: the Home tab, terminal tabs, the context bar, ⌃`, ⌘\, closing the active tab returns Home.

## 2. Features

### 2.1 The workbox row
- **Contents:** Home first, then a divider, then one tab per workbox that has open terminal tabs.
  - Workboxes appear in the sidebar's machine order (the existing `groupTabs` order, strays last).
  - A workbox with no open tabs has no tab here.
- **Home tab:** the home icon and the word "Home". Its tooltip is "Home (⌘1)". It is never closable.
- **A workbox tab** shows:
  - its health dot;
  - its label, in mono, semibold;
  - its open-tab count, in a small grey pill;
  - when any of its tabs is blocked on the user, an orange badge with an exclamation icon and the number. The badge's text for assistive tech is "{N} needs input".
- **Accessible name:** "{label}, {health word}, {N tab|tabs}", plus ", {N} needs input" when that applies. It is a real `<button>` inside a `nav` labelled "Workboxes".
- **Active workbox:** the one that owns the active terminal tab. While Home is active, the Home tab is the active one and no workbox is.
- **Look:** a tab with rounded top corners (10 px). The active tab takes the session row's background and joins it, with inverse-curved bottom corners, as Chrome draws it. Inactive tabs have no fill and show a hover fill.
- **Clicking a workbox tab** activates the tab last active on that workbox while the app runs, else its first tab in open order.
- **Overflow:** if the workbox tabs don't fit, the row scrolls sideways and keeps the active one in view.

### 2.2 The session row
- **When a workbox is active**, it shows only that workbox's terminal tabs, in the order they were opened.
- **A session tab** has two lines:
  1. the status dot and the tab title, in mono;
  2. "{project} · {status words}" in small grey text. The project is the row's project name (as `projectNames` gives it), else the folder's short path. With neither, the line is the status words alone.
- **Status words**, all spelled out on the tab: "Working", "Idle", "Needs input", "Done, unseen", "Unknown", "Shell", and, while there is no live session, "Opening…", "Detached", "Error" (combined as today: "Detached · Needs input"). They are `tabStatus`'s words, so the strip, the All tabs menu and the sidebar still agree.
  - "Needs input" is orange and "Done, unseen" is the done blue; the others are grey.
- **A full-UI tab** reads "herdr" over "Full herdr UI".
- **Needs input:** a tab whose agent is blocked on the user has a light orange tint. While it is the active tab, it instead shows an orange top edge.
- **Active tab:** the context bar's background, joined to the bar below with inverse-curved corners. Inactive tabs show a hover fill.
- **Close:** each tab has a close button ("Close tab {title}"), the same detach as ⌘W.
- **Size:** tabs are 160–228 px wide and shrink toward 160 px before the row overflows.
- **Overflow:** past that, the row scrolls sideways and keeps the active tab in view. The **All tabs** menu button sits at the end of the row; it still lists every tab by workbox with its status and shows the needs-input count.
- **New session:** the row ends with "+ New on {workbox label}". It opens the New session sheet with that workbox filled in (`openNewSession({ machineId })`).
- **Tooltip:** a tab's tooltip is its status words and, for the first eight tabs in strip order, its shortcut (⌘2–⌘9).

### 2.3 The session row while Home is active
- It shows the Home views as tabs: **Dashboard** and **All agents**, plus the open Workbox screen's label while Home is showing one.
- The tab for the current view is highlighted. Clicking one shows that view (`showHomeView`).
- The pinned Home tab's label is now always "Home"; the view's name moves to this row.

### 2.4 Copying a terminal link
- **Behaviour (unchanged):** links in a terminal are copy-only. ⌘-click copies the URL and shows "Link copied"; a plain click does nothing; the app opens no URL but herdr.dev.
- **Bug:** the copy fails on WebKit with `NotAllowedError` ("The request is not allowed by the user agent or the platform in the current context…") from `navigator.clipboard.writeText`, so the user sees an error toast and nothing is copied.
- **Fix:** find the root cause first. Unless it turns out to be something else, the copy goes through the Rust side (Tauri's clipboard-manager plugin, write-text only, allowed for the main window), not the web clipboard API.
  - One shared helper does every copy in the app: the terminal link, Copy attach command (`OpenButton`) and the command box (`CommandBox`). They all have the same exposure.
  - On failure the toast still says "Couldn't copy to the clipboard."; on success, the existing "Link copied" / "Copied" toasts.
- **No reading the clipboard.** The capability grants writing text only.

### 2.5 Unchanged
- ⌘1 goes Home; ⌘2–⌘9 select terminal tabs in flat strip order across workboxes (workboxes in machine order, tabs in open order).
- ⌃Tab and ⌃⇧Tab cycle through Home and every tab in that order. ⌘W, ⌃`, ⌘\ and ⌘J are unchanged.
- Closing the active tab returns Home. Closing a workbox's last tab removes its workbox tab.
- The context bar, the 16-tab cap, and inactive terminals staying mounted (hidden) are unchanged.

## 3. Non-goals (v0.4)
- No age on session tabs ("Needs input · 2m"). The data exists; the maintainer chose to leave it off.
- No dragging tabs or workboxes to reorder them.
- No per-workbox colours; a workbox is identified by its label and health.
- No shortcut to move between workboxes.
- Links never open, in-app or in a browser.

## 4. Anti-goals
- Status shown by colour alone (the badge has its words for assistive tech; every tab has its status words).
- Switching workbox or Home view losing a terminal's scrollback, or detaching it.
- A keystroke typed in a terminal acting on the tab rows (v0.2 §4 still holds).
- The clipboard capability allowing reads.

## 5. Architecture notes
- **`terminalStore`:**
  - removes `folded`, `toggleFold` and the unfold step in `openTab` and `activate`;
  - gains `lastByMachine: Record<machineId, tabKey>`, set by `openTab` and `activate`, and cleaned up by `closeTab`;
  - gains `activateMachine(machineId)`: the remembered tab, else the workbox's first tab in open order.
- **`TabStrip.tsx`** becomes a small composer over:
  - `WorkboxRow.tsx`: row 1, with its own `nav` "Workboxes";
  - `SessionRow.tsx`: the session tabs, "+ New on {workbox}" and `AllTabsMenu`;
  - `HomeViewsRow.tsx`: row 2 while Home is active.
- **`tabOrder`:** `groupTabs`, `stripOrder` and `tabShortcut` stay as they are.
- **`tabInfo`:** gains `tabSubline(tab, row, project)`, the second line of a session tab. `tabChip` goes away if nothing else uses it.
- **Callers of folding** (sidebar, palette, menu actions, notifications) lose the fold code; activating a tab already makes its workbox active.
- **Styles:** the `.tab-group*` and `.ws-tab` rules in `app.css` are replaced by rules for the two rows and their tabs. Colours come from `tokens.css` only; new tokens are added there if needed.
- **Clipboard:** a `copyText(text)` helper in `lib/` is the only place that writes the clipboard. The Rust side adds `tauri-plugin-clipboard-manager`, and the main window's capability allows `clipboard-manager:allow-write-text` and nothing else from it.
- **Tests (TDD):**
  - store: last tab per workbox, `activateMachine`, cleanup on close;
  - `WorkboxRow`: accessible names with the needs count, a click restoring the last tab;
  - `SessionRow`: only the active workbox's tabs, the second line for every state, the New-on prefill, the overflow menu;
  - `HomeViewsRow`: switching views;
  - `copyText`: success and failure toasts at each of the three call sites, with `lib/ipc.ts` (or the plugin's JS module) mocked;
  - fold tests are deleted.
- **GUI-only checks** go in `docs/qa-checklist.md`: the Chrome-style joins, scrolling and the active tab staying in view, and ⌘-click copying a link in the real webview.
