# crafted-herdr-ui v0.5: readability pass and Homebrew install (design addendum)

Date: 2026-10-20
Status: approved in conversation. On 2026-10-20 the maintainer approved the Claude Design canvas "Crafted Herdr readability pass" (https://claude.ai/artifact/67tzhcDAmsX6132AY6kKW8) as presented, and chose "ship the cask with the one-time Open Anyway step" for Homebrew (§4). The canvas is the visual reference; this text is the authority.
Extends: the v1 design and the v0.2, v0.3 and v0.4 addenda. They all still hold unless this addendum overrides them. Where they disagree, this addendum wins.

## 1. Intent

The maintainer compared our project site and app with herdrui.dev (Herdr UI) and herdrweb.dev (Ovis). What they liked there was **the font sizes and how easy everything is to read**. They want ours to **keep its personality** (Instrument Serif headlines and amber on the site; Geist and the dark status palette in the app) and become easier to read and more polished. They also want an **install via Homebrew**, the way herdrui.dev offers `brew install penso/tap/herdr-gpui`.

Three parts, all on one branch (`feat/v0.5-readability-homebrew`):
1. **Project site** (`site/index.html`): a new type scale and calmer details; feature rows with screenshots; an install card with Homebrew first (§2).
2. **App**: a new type scale and brighter secondary text, through tokens (§3).
3. **Homebrew**: a personal tap, a cask, and the release workflow keeping it current (§4).

### Goals
- Nothing a user needs to read is smaller than 12 px in the app or 13 px on the site.
- Secondary text is clearly readable on the dark ground, not just "passing contrast".
- Someone who lands on the site can install with one copied command.

### Non-goals
- No new app features and no layout changes beyond sizes and spacing. Screens keep their structure.
- No change to the terminal (xterm) font or its size.
- No light theme.
- No notarization in this release. The README's "Optional: Developer ID signing and notarization" section stays as the upgrade path.
- No Linux or Windows install.

### Anti-goals (a failure even if it "works")
- Losing the personality: replacing Instrument Serif headlines, the amber signal color or Geist with a generic system-font look.
- **The cask working around Gatekeeper**: no `postflight` that clears `com.apple.quarantine`, no `--no-quarantine` advice, no anything that does it for the user. Homebrew 5.0 deliberately removed that, and the app's own rule 5 ("never acts for the user on risky things") points the same way.
- Text that now truncates or wraps badly at the app's minimum window size or in the narrow Dashboard split column.

## 3. App

The canvas boards "App: Dashboard, easier to read" and "Type scale: before and after" show this.

### 3.1 Type scale through tokens
Today `src/styles/*.css` has about 110 literal `font-size`s, mostly 11–12.5 px, and `tokens.css` has only `--font-size: 13px`. v0.5 adds a small scale to `tokens.css` and every `font-size` in the app's CSS uses one of the tokens (no literal px sizes left outside `tokens.css`):

| Token | Size | Replaces today's | Used for |
|---|---|---|---|
| `--fs-hint` | 12 px | 10.5 px | shortcut hints (⌘1, ⇧⌘A), tiny counts |
| `--fs-small` | 12.5 px | 11, 11.5 px | second lines ("Online"), group headers, captions, metric labels |
| `--fs-meta` | 13 px | 12 px | row details, tab second lines, chips |
| `--fs-body` (= `--font-size`) | 14 px | 12.5, 13 px | base text, buttons, inputs, sidebar items, mono agent names in rows |
| `--fs-lead` | 16 px | 15 px | section titles, card titles |
| `--fs-title` | 18 px | 17, 18 px | sheet and dialog titles |
| `--fs-display` | 2 px up per step | 20, 22, 26 px | screen titles and metric numbers |

The mapping column is a starting point: where a role clearly belongs to a different step, the builder moves it. Mono text follows the same steps.

### 3.2 Secondary text color
- No text that conveys information is dimmer than `#9a9da6` on `--bg` (about 7:1). `--text-4` and `--muted` become `#9a9da6`; `--text-3` stays `#a3a5ad`. Placeholders and disabled text may stay dimmer.
- Status colors and their words are unchanged (status is never color-only).

### 3.3 Spacing and casing
- **Comfortable** (the default `row_density`): agent rows, sidebar items and list rows are at least 40 px tall (sidebar items with a second line, about 48 px). Buttons are 36–38 px.
- **Compact** keeps today's tighter spacing (rows about 34 px) **at the new type sizes**; its Settings hint text stays. It reaches exactly what `.density-compact` touches today (`.row-main`, `.agent-row`, `.group-head`, `.group`, `.card`, `.cards`, `.main`, in the main window). Sidebar items and buttons get the new sizes in both densities, and the popover and Settings windows don't follow the setting. CSS-only; no new wiring.
- Uppercase, letter-spaced group headers ("WORKBOXES", "PROJECTS") become sentence case, 12.5 px, weight 500, 0.04em ("Workboxes").
- The popover (`popover.html`) and the Settings window take the same tokens.

### 3.4 Where it must still fit
Check after the change, and fix by wrapping, ellipsis or a sensible min width (never by shrinking type back):
- the minimum window size and the sidebar at its width; the collapsed ⌘B rail;
- the two-row tab strip: workbox tabs and the 160–228 px session tabs;
- the narrow Dashboard split column (360 px minimum);
- the context bar, the command palette, the Activity drawer, sheets and dialogs, the menu bar popover.
These are GUI checks: they go into `docs/qa-checklist.md` for the maintainer pass, in addition to whatever the tests can cover.

### 3.5 App constraints
`src/CLAUDE.md` holds: colors and sizes only from `tokens.css`; Geist and Geist Mono stay bundled, no network fonts; real buttons and focus rings. `styles.test.ts` is extended so a literal px `font-size` outside `tokens.css` fails the test.

## 4. Homebrew

### 4.1 The tap
- A new public repository **`valencar/homebrew-tap`**, so the install is `brew install --cask valencar/tap/crafted-herdr` (and `brew install valencar/tap/crafted-herdr` also resolves).
- **The agent sets up the tap with `gh`, and asks the maintainer in chat before each outward-facing step:** creating the public repo, its first push (the v0.4.0 cask and README), and any later push. The builder prepares the contents in this repo first (§4.2).
- **The token is the maintainer's to make.** A fine-grained token can only be created on github.com. The maintainer creates it and stores it themselves with `gh secret set HOMEBREW_TAP_TOKEN --repo valencar/crafted-herdr-ui`, which prompts for the value, so the agent never sees or handles it (CLAUDE.md rule 2).
- It holds `Casks/crafted-herdr.rb` and a short README (what it is, the install and upgrade commands, the first-launch note, a link back here). MIT, like this repo.

### 4.2 The cask
Kept as a template in this repo, `packaging/homebrew/crafted-herdr.rb` (version and sha256 filled in at release time), and copied into the tap. It contains:
- `version`, `sha256` of the universal DMG;
- `url "https://github.com/valencar/crafted-herdr-ui/releases/download/v#{version}/Crafted.Herdr_#{version}_universal.dmg"` (the asset name `tauri-action` produces today);
- `name "Crafted Herdr"`, a one-line `desc`, `homepage "https://valencar.github.io/crafted-herdr-ui/"`;
- `livecheck` on the GitHub latest release;
- `depends_on macos: ">= :ventura"` (macOS 13, matching `minimumSystemVersion`);
- `app "Crafted Herdr.app"`;
- `caveats`: herdr must be installed separately; builds aren't notarized, so open the app once and choose Open Anyway in System Settings › Privacy & Security;
- `zap trash:` the app's data for bundle id `dev.crafted.herdr-ui`: `~/Library/Application Support/dev.crafted.herdr-ui`, `~/Library/Caches/dev.crafted.herdr-ui`, `~/Library/WebKit/dev.crafted.herdr-ui`, `~/Library/Preferences/dev.crafted.herdr-ui.plist`, `~/Library/Saved Application State/dev.crafted.herdr-ui.savedState` (the builder confirms the real paths on a machine; `zap` never touches herdr's own files).
- **No** `postflight`, `preflight` or `quarantine` handling (§1 anti-goals).

### 4.3 Keeping it current
- A new job in `release.yml`, after "Publish the release": download the published DMG, compute its sha256, fill the template, and commit `Casks/crafted-herdr.rb` to `valencar/homebrew-tap` with the message `crafted-herdr {version}`.
- It authenticates with a repository secret **`HOMEBREW_TAP_TOKEN`**: a fine-grained token with Contents: write on the tap repo only. The maintainer creates it. If the secret is missing, the job logs a notice and succeeds, so a release is never blocked by the tap.
- A tag with a hyphen (`v0.5.0-rc.1`) doesn't update the tap. The project doesn't publish prereleases today, and how `release.yml` publishes releases otherwise doesn't change.
- **Site freshness:** `pages.yml` listens for `release: published`, but the release is published with `GITHUB_TOKEN`, which starts no other workflow, so the site's DMG link only moves on the next push to `site/`. The release job therefore ends with `gh workflow run pages.yml` (a `workflow_dispatch`, which `GITHUB_TOKEN` may start; the job needs `actions: write`).
- CI (`ci.yml`) checks the template: Ruby syntax at least; `brew style` on a macOS runner if it's cheap enough (builder's call).
- **Bootstrapping:** the agent publishes the first cask (for the current release, v0.4.0) to the tap, after the maintainer's OK, so the command on the site works before the next release. It then runs `brew install --cask valencar/tap/crafted-herdr` once to confirm it resolves and installs, and reports the result.

### 4.4 README and release notes
- README "Install" becomes: Homebrew first (the command, the upgrade command), then the DMG, then the existing first-launch steps, unchanged.
- The release notes' "Install" paragraph in `release.yml` mentions the brew command next to the DMG.

## 5. Order of landing
The site must not advertise a brew command that doesn't work. So: the tap exists and holds the v0.4.0 cask **before** the site change merges to `main` (the Pages workflow deploys on merge). App type changes ship in the next tagged release.

## 6. Global constraints (unchanged, restated)
- No personal data: only the generic examples (`buildbox`, `gpubox`, `staging`; `api-service`, `web-app`, `infra`) in mockups, fixtures and screenshots. `valencar` (the public repo owner) is already public in the site and README. Run `scripts/check-no-personal-data.sh` before every commit.
- No secrets in the repo; the tap token lives only in repository secrets.
- TDD for app code; `pnpm lint && pnpm typecheck && pnpm test`, and the Rust checks if Rust is touched (it shouldn't need to be).
- No pushing to `origin` unless the maintainer asks.

## 9. Security hardening (added 2026-10-20 at the maintainer's request)

A read-only security review on 2026-10-20 found no secrets or personal data in the tree or history, and no critical or high issues. The maintainer asked for these fixes on this branch. Branch and tag protection on GitHub is **not** part of it.

### 9.1 Release build without a write token
- `release.yml` splits into:
  - a **build** job: `permissions: contents: read`, `actions/checkout` with `persist-credentials: false`, no `GITHUB_TOKEN` in any step's env. It builds the universal app and DMG (with `tauri-action` in build-only mode, or `pnpm tauri build --target universal-apple-darwin` directly) and uploads the DMG and `.app.tar.gz` as a workflow artifact;
  - a **publish** job: `needs: build`, `permissions: contents: write, actions: write`, **no checkout of dependencies and no `pnpm install`/`cargo`**. It downloads the artifact, writes `SHA256SUMS.txt` for the assets, creates the release as a draft with the assets, generates the notes as today, publishes it as Latest, and dispatches Pages (§4.3).
  - The `tap` job (§4.3) `needs: publish`.
- Asset names stay `Crafted.Herdr_<version>_universal.dmg` and `Crafted.Herdr_universal.app.tar.gz`, so the site and the cask keep working.

### 9.2 Pinned actions
- Every `uses:` in `ci.yml`, `release.yml` and `pages.yml` is pinned to a full 40-character commit SHA with the version as a trailing comment (`uses: actions/checkout@<sha> # v4.2.2`). `dtolnay/rust-toolchain` is pinned by SHA with `toolchain: stable` as an input.
- `.github/dependabot.yml` updates `github-actions` weekly.
- Turning on Dependabot alerts and security updates is a repository setting: the agent does it with `gh api`, after the maintainer's OK (plan Task 7).

### 9.3 `pages.yml`
- The release tag reaches `build-site.sh` through `env:` (`TAG`), never through `${{ }}` inside `run:`.
- `pages: write` and `id-token: write` move from the workflow to the `deploy` job; the workflow default is `contents: read`.

### 9.4 Per-window app commands
- `src-tauri/build.rs` declares every app command through `tauri_build::Attributes::new().app_manifest(tauri_build::AppManifest::new().commands(&[...]))`, so each needs an explicit `allow-<command>` permission.
- Each capability file grants only what its window calls:
  - `popover.json`: the commands `src/popover.tsx` and what it renders call (today: `get_state` or the state read it uses, `show_main`, `show_main_open_row`, `show_main_new_session`, `open_settings` if used);
  - `settings.json`: what the Settings window calls (`get_settings`, `set_settings`, `preview_launch_template`, `get_terminals`, `list_terminals`, `machine_set_enabled`, `herdr_status`, `shortcut_status`, and any other the screen uses);
  - `default.json` (main window): everything the main window calls.
  The exact lists come from the code, not from this text. A command no window calls is granted to none.
- Neither the popover nor Settings may call `term_write`, `term_open`/session commands, or any herdr-mutating command they don't use. The popover may not call `set_settings`.
- `core:default` stays as it is (narrowing it is out of scope).

### 9.5 System tools by absolute path
- The app runs `/usr/bin/open`, `/usr/bin/osascript` and `/usr/bin/mdfind` by absolute path, never through the captured login `PATH`. Comparisons on the program name (launch timeouts, the Automation error message) keep working.
- `ssh` and `herdr` stay resolved through the user's PATH on purpose (people use Homebrew OpenSSH and custom herdr installs).

### 9.6 `.gitignore`
- Adds key material: `*.pem`, `*.p12`, `*.p8`, `*.key`, `*.cer`, `*.mobileprovision`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*`.

### 9.7 Out of scope
Branch and tag protection rulesets; self-hosting the site's fonts; narrowing `core:default`; moving the commit email to the noreply address.
