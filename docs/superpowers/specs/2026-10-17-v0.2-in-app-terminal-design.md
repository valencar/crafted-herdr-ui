# crafted-herdr-ui v0.2: in-app terminal and faster navigation (design addendum)

Date: 2026-10-17
Status: approved feature set (maintainer, 2026-10-17)
Extends: `2026-10-16-crafted-herdr-ui-design.md` (the v1 spec). Everything there still holds unless this addendum overrides it. Where the two disagree, this addendum wins.

## 1. Intent

v1 opens panes in the user's own terminal app, so working with several agents means switching windows all day. The maintainer asked to "control everything in one app": open a pane in a terminal **inside the window, like VS Code does**, and keep "Open in iTerm/Ghostty/Warp…" for when a separate window is wanted. The rest of v0.2 makes moving between agents fast: one palette instead of many shortcuts, a jump to the next agent that needs you, and tabs.

### What this overrides in the v1 spec
- **§3 "No embedded terminal emulator"** is lifted. The app now hosts terminals. Herdr still owns every process. The in-app terminal is just one more attach client running the same command "Open in…" runs.
- **§1 "The app is a control plane, not a terminal"** becomes: the app is a control plane *with* a terminal. Typing can happen in the app or in the user's terminal, whichever they choose.

## 2. Features

### 2.1 Built-in terminal panel (the core)
- **Panel:** a panel inside the main window that hosts terminal tabs.
  - It sits at the bottom of the window or on its right; the right side is the split view.
  - It can be resized by dragging and toggled with ⌃`.
  - It lives at the app level, so its tabs survive moving between Home and a Workbox screen.
- **Tabs:**
  - Each tab is one attach session to one herdr pane, or to a machine's full herdr UI when Settings › attach mode is "full UI".
  - A tab shows the agent's name, the workbox label and the live status dot with its text label (the v1 rule "status is never colour-only" applies).
  - A tab whose agent needs input is highlighted.
- **Open here vs Open in:**
  - A new setting, `open_target` (`app` | `external`, default `app`), decides what "Open" does everywhere: rows, needs-you cards, the Inspector, ⌘↩, the palette, notifications and the menu-bar popover.
  - The Inspector and the needs-you cards also offer the other choice as a second button ("Open in {Terminal}", or "Open here").
  - Opening a pane that already has a tab focuses that tab instead of attaching twice.
- **What runs in a tab:** exactly the v1 attach command for that pane (`attach_for_pane` / `open_argv`).
  - It runs on a pty sized to the tab, with the captured login environment plus `TERM=xterm-256color` and `COLORTERM=truecolor`.
  - Remote panes go through `ssh -t`, local panes through the resolved herdr binary.
  - The takeover prompt and the "herdr not found" message from the v1 attach script show up inside the tab, and the user answers them there.
- **Closing a tab only detaches:**
  - It ends the attach client (the pty child) and never the herdr pane or the agent.
  - "Close pane" stays its own action, with its v1 confirmation.
  - When the attach ends on its own (herdr's detach key, ssh drop, takeover elsewhere), the tab stays open in a "Detached" state with "Reattach" (Enter) and "Close tab" (⌘W).
- **Terminal behaviour:**
  - Geist Mono; colours come from design tokens, including 16 ANSI colour tokens.
  - Copy and paste through the native Edit menu.
  - ⌘F finds in the active tab. ⌘+, ⌘− and ⌘0 change the terminal font size, which is persisted.
  - Scrollback is 10,000 lines. The tab resizes to fit the panel.
  - It uses the WebGL renderer when available and falls back to the DOM renderer.
- **Links are copy-only** (the maintainer accepted this default). ⌘-clicking a URL copies it to the clipboard and shows "Link copied". The app still opens no URL other than `https://herdr.dev` (the v1 rule).
- **Logged:** each in-app attach appears in the Activity drawer as a launch entry with the note "opened in Crafted Herdr", like "Open in…" launches today.
- **Limit:** at most 16 open tabs. A 17th open shows "Close a terminal tab first (16 open)."
- **Not restored at launch:** tabs are never reattached automatically, so the app never takes a session over by itself.

### 2.2 Navigation
- **⌘K command palette:**
  - It fuzzy-searches agents and panes (name, workbox, folder, status), projects, workboxes and commands.
  - Commands: New session, Add workbox, Toggle terminal, Toggle split, Next needs-you, Settings, Activity, Refresh.
  - Enter runs the default action. On an agent or pane that is Open (by `open_target`); ⌘Enter opens it the other way.
  - The Home search box moves from ⌘K to ⌘F when focus isn't in a terminal.
- **⌘J, next needs-you:** selects and opens the next agent in `needsYou(rows)` order (blocked first, then oldest), after the current selection, wrapping around. With nobody waiting it shows the toast "Nobody needs you right now."
- **Tabs:** ⌘1–⌘9 select a tab, ⌃Tab and ⌃⇧Tab cycle, and ⌘W closes (detaches) the active tab. With no tab open, ⌘W does nothing; the window's close button still hides the window.
- **Notifications:** clicking one selects the row and opens it (by `open_target`).
- **Menu-bar popover:** its "Open" brings the main window forward and opens the row there when `open_target` is `app`.

### 2.3 Layout
- **Split view (⌘\):** toggles the terminal panel between bottom and right. While it's on the right, the Inspector column is hidden; its actions stay reachable through the palette and the row buttons.
- **Sidebar:** collapses with ⌘B to an icon rail.
- **Row density:** `comfortable` (default) or `compact`, in Settings › Appearance.
- **Persisted:** window size and position (official `tauri-plugin-window-state`), panel placement, panel size, terminal font size, sidebar collapsed and density, all in Settings.

### 2.4 Native app menu
The app installs its own macOS menu, replacing Tauri's default one.
- **Menus:**
  - App: About, Settings ⌘,, Hide ⌘H, Hide Others ⌥⌘H, Quit ⌘Q
  - Edit: Undo, Redo, Cut, Copy, Paste, Select All
  - View: Command Palette ⌘K, Toggle Terminal ⌃`, Toggle Split ⌘\, Toggle Sidebar ⌘B, Next Needs-You ⌘J, Find ⌘F, Bigger/Smaller/Reset Font ⌘+/⌘−/⌘0, Activity ⇧⌘A
  - Terminal: Close Tab ⌘W, Next Tab ⌃Tab, Previous Tab ⌃⇧Tab, Tab 1–9 ⌘1–⌘9
  - Window: Minimize ⌘M, Bring All to Front
- **Why a native menu:**
  - its accelerators fire even while the terminal has keyboard focus;
  - they are discoverable in the menu bar, which answers the v1 "too many shortcuts to remember" pain;
  - it frees ⌘W from "Close Window".
- **How it works:** each item emits a `"menu"` event to the main window with the item id, and the UI acts on it. Existing in-page shortcuts (⌘N, ⌘R, ⌘↩, arrows, Backspace) keep working when focus is not in a terminal.
- **Keys typed in a terminal belong to the terminal:** Backspace, Delete, arrows, ⌃C and the rest never trigger Home's list shortcuts.

## 3. Non-goals (v0.2)
- No git diff panel. It would need git over SSH, which goes beyond "herdr CLI only".
- No popping a tab out into its own window.
- No auto-reattach of tabs at launch.
- No clickable links that open a browser.
- No keybinding editor.
- No terminal for arbitrary local shells outside herdr. Every tab is a herdr attach.

## 4. Anti-goals
- Closing a tab, quitting the app or a crash ends a herdr pane or agent. Only the attach client may end.
- The app taking a session over without the user answering the takeover prompt.
- A keystroke meant for the terminal triggering an app action. The worst case is Backspace opening "Close session".
- An output burst (an agent redraw, a big `cat`) freezing the UI or growing memory without bound.
- Garbled text when a multibyte character is split across reads.

## 5. Architecture
- **Rust, `src-tauri/src/pty.rs` (new):**
  - `PortablePty` / `PtySpawner` / `SpawnedPty` / `PtyControl` move here from `machine_setup/mod.rs`, which keeps using them.
  - A spawn takes a size, and `PtyControl` gains `resize(cols, rows)`.
- **Rust, `src-tauri/src/terminal/session.rs` (new):**
  - `TermSessions` owns the open sessions (id → writer, control, reader thread).
  - The reader thread decodes UTF-8 incrementally (it keeps a split sequence for the next read) and pushes `TermEvent::Data{data}` / `TermEvent::Exit{code}` to a sink.
  - The sink is a `tauri::ipc::Channel<TermEvent>` in the app and a closure in tests.
  - When the sink fails (the webview went away), the session is closed.
  - All sessions are killed when the app exits.
- **Commands:** `term_open`, `term_write`, `term_resize` and `term_close` (see the plan for exact signatures).
- **Menu:** a new `src-tauri/src/menu.rs`.
- **UI, `src/terminal/` (new):**
  - `terminalStore` (tabs, active tab, panel open, placement, size, font size);
  - `useTermSession` (Channel, write, resize, close, the detached state);
  - `TerminalView` (one xterm instance per tab, kept mounted while hidden so scrollback survives tab switches);
  - `TerminalPanel` (tab strip, resize handle, find bar).
- **UI, other new files:** the palette in `components/CommandPalette.tsx`, with pure ranking in `lib/fuzzy.ts` and `lib/palette.ts`.
- **Dependencies (pinned, bundled, no CDN):** `@xterm/xterm` 6.0.0, `@xterm/addon-fit` 0.11.0, `@xterm/addon-search` 0.16.0, `@xterm/addon-webgl` 0.19.0, `@xterm/addon-web-links` 0.12.0, and the Rust crate `tauri-plugin-window-state` 2.x. The CSP needs no change: xterm uses inline styles, which are already allowed, and no workers.
