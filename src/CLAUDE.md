# src: React UI

The UI renders `AppState` pushed from Rust (`"state"` event) and calls typed Tauri commands. All view logic (needs-you, grouping, sorting, ages, names) is pure TypeScript in `lib/`, and it's unit-tested.

## Layout

## Rules

- **Windows get only the commands they invoke.** Each window (main, popover, Settings) has its own capability file in `src-tauri/capabilities/` granting exactly the app commands its code calls. A new `invokeTyped` (or `invoke`) call reachable from a window needs that window's grant, plus the command in `generate_handler!` and `build.rs` `COMMANDS`; `scripts/capabilities.test.ts` fails on a missing or extra grant.
- **`useNow` lives in `lib/useNow.ts` on purpose.** It used to sit in `lib/uiHelpers.ts`, which imports `saveSettings`; keeping it in its own file keeps the popover's import graph free of `set_settings`, which the popover window is not granted.
- **Identity:** a row key is always `${machineId}::${address}`; `machineId` is `"local"` or the core's machine id, and `address` is local to that machine (`t7`). Addresses repeat across machines; never key by address alone. Calls take `row.fullAddress` (`t7`, or `<machine name>/t7`). 
- **Workbox color comes only from `data-wb-color` + `--wb` / `--wb-fill`.** A component sets `data-wb-color` (through `useWorkboxColor`) and styles with `var(--wb)` and `var(--wb-fill)`; the `[data-wb-color]` rules in `app.css` ("Workbox colors") map the name to `--wb-<name>` from `tokens.css`, with `--wb-none` as the fallback. Never a color name or a `--wb-<name>` token in a component. Tints are `color-mix(in srgb, var(--wb) var(--wb-mix), var(--bg))` (`--wb-mix` is 18% in dark, 10% in light) and text on a tile uses `--on-wb`. Home stays neutral, and the workbox name always stays beside its tile.
- **Status is never color-only.** Every status shows its text label too: "Needs input", "Error", "Done, unseen", "Working", "Idle", "Ended", "Unknown", "Shell". Needs you is blocked, error, or done and unseen (a worker's done excluded); the tab badges (`countNeeds`) count blocked and error only. A worker's done reads "Done" and ranks, counts and is drawn with Idle (spec 4.5): everything that orders, counts or names rows by status goes through `shownStatus(row)` in `lib/grouping.ts` (`StatusPill` with `isWorker`, the sidebar's project dot, Group by Status, `statusCounts`, the palette, the tabs, the popover, the tails' order). Error is the needs shape (filled, halo, pulse while `live`) in `--danger`; Ended is a static hollow square in `--text-3`, never needs-you, sorted after the other rows of its group, and its row's second line reads "Ended · exit 1" (or "Ended · {reason}" with no code; `endedDetail`). The Dashboard gives an errored agent a Needs you card and its Agents tile and bar count error and ended (named in the legend only when there are some).
- **Colors and sizes come from `tokens.css` variables.** No hex literals in components.
- **Shortcut labels come only from `Kbd` / `formatShortcut`.** Never type `⌘K`, `⇧⌘A` and the like in a component; add the id to `lib/shortcuts.json` and draw it with `Kbd` (or `formatShortcut(id)` where a string is needed, such as an `aria-label`).
- **Tooltips come only from `Tooltip`.** No native `title=` attribute on a control (a `title` prop on `Section`, `EmptyState` or a sheet is a heading, not a tooltip). The control keeps its own `aria-label`; the tooltip is `aria-hidden`.
- **Status indicators come only from `StatusDot` / `HealthDot`.** Never a bare colored dot. `live` (the looping animation) is passed only where the v0.7 spec's §3.3 allows it: the sidebar, both tab rows, the context bar, the palette and the Dashboard's Needs you cards. Static everywhere else, decided by where it is mounted, never by counting rows.
- **Motion goes through the tokens.** Durations are `--dur-fast`, `--dur-base` and `--dur-slow` and easing is `--ease-out`; no literal `ms` or `cubic-bezier` in a component stylesheet. Only `transform`, `opacity` and colors animate, nothing that resizes the terminal (the sidebar collapse, the split column, window resize) animates, and everything that loops or enters stops under `prefers-reduced-motion: reduce`.
- **Home tab and the hidden screens.** `App` mounts the current Home screen (Dashboard, AllAgents or Workbox) inside `Workspace`, and it stays mounted, hidden, under a terminal tab. So anything that polls or reads the core from it must also stop while `useHomeVisible()` is false: the Inspector's preview and the Workbox tail reads (`useTails`) pause, and the Dashboard's command-log read stops. The Dashboard makes no core calls; it reads `state`, `settings`, the terminal store and `get_command_log` (every 5 s, only while visible and the window is shown). Closing the active terminal tab makes Home active.
- **The one URL:** the app opens `https://herdr.dev` (Onboarding) through `plugin-opener`; the main window's capability allows that URL and no other. No other link, fetch or `<a href>` to the web.
- **Keys typed in `.terminal-panel` belong to the terminal.** The list shortcuts and every other key handler skip an event whose target is inside it (`isInTerminal` in `lib/uiHelpers.ts`); only the native menu's accelerators act there. The list's own keys (arrows, Backspace/Delete, ⌘↩) also act only while the Home tab is active and shows All agents, so a key pressed on the tab strip, the context bar or `document.body` over a terminal never selects, opens or closes a row in the hidden list. The terminal never takes focus while a sheet or dialog is open.
- **Links in a terminal are copy-only.** ⌘-click copies the URL and shows "Link copied"; xterm's web-links addon never opens one. The copy goes through `copyText` like every clipboard write (never `navigator.clipboard`); a refused write shows the error toast "Couldn’t copy to the clipboard.", never "Link copied". No terminal text becomes a command: `term_write` carries only keystrokes and pastes.
- **Fonts:** Geist, Geist Mono, Hack, IBM Plex Mono and JetBrains Mono are bundled under `fonts/` as the full, unmodified upstream woff2 files (declared in `styles/global.css`; each license sits next to the files), so box drawing, arrows, geometric shapes and accented letters come from the chosen font, not a fallback. The UI's `--font-sans` and `--font-mono` stay Geist and Geist Mono; only the in-app terminal follows the `terminal_font` setting (`hack` by default, then `ibm_plex_mono`, `geist_mono`, `jetbrains_mono`), which `terminal/terminalFonts.ts` maps to a label, a family stack, the weights and `lineHeight: 1.2`. The stylesheets set no `-webkit-font-smoothing` (a test enforces it), so macOS draws text at its normal weight. No network font loading, and no network calls at all.
- **Accessibility:**
  - real `<button>`, `<a>` and `<input>`/`<label>`, with a visible focus ring;
  - `aria-label` on icon-only buttons;
  - destructive actions always go through `ConfirmDialog`, which renders on the body (so it stays visible when a terminal tab hides the Home slot it was opened from).
- **Copy:** monospace for ids, paths, commands and terminal output; sans for everything else.
- **CLI transparency:** show the exact command for an action where the design does (command box, new-session preview). The text comes from Rust (`previewNewSession`, `copyAttachCommand`), never rebuilt in TS.
- **Unknown inputs:**
  - agent names may be `null`, so use `displayName`;
  - ages may be `null`, so render nothing rather than guessing.

## Testing

- **Vitest + React Testing Library.** Mock `lib/ipc.ts`, not Tauri internals.
- **Test data** comes from `test/builders.ts`, with generic names only (`buildbox`, `api-service`, `/home/dev`); a test doesn't import `src-tauri/tests/fixtures/hc/` files except to check the shape the core really sends (`detachReason.test.ts`). The command-log entries in tests use `hc` lines and the core's method names (`machine.list`, `terminal.kill`), never the retired `herdr` ones.
- **Before committing:** `pnpm lint && pnpm typecheck && pnpm test`.
